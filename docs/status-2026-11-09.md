# 开发记录

## 2026-11-09：触摸驱动的两条路只能走一条；GPU 的结论

### 1. 触摸"突然没了"的原因：两套驱动抢同一颗芯片

给内核加了 `fts=1` 之后触摸失效。日志里能同时看到两条链路在动同一颗 FTS：

```
touch: L28 (AVDD) requested over RPMh, at 42100     ← loader 的触摸服务（UEFI）
touch: scanning
touch: chip id 36 39
touch: 28928 polls, 451 reads, 0 events, 0 fails    ← 服务在扫，却拿不到事件

fts: step 1: the clocks of serial engine 14 ...      ← 内核内 FTS 驱动（perseus_fts.c）
fts: step 2: the pins and the supplies
```

两套实现都要配置 GPIO / I2C / 复位线，互相打断，结果是一颗也没有可靠驱动。

**结论：这台手机的触摸只保留一条路——loader 驱动芯片，内核读共享页。**

- 用：`loader/touch.c` + `kernel/perseus_touch.c`，启动参数带 `touch_shared_pa=…`，**不要 `fts=1`**；
- 不用：内核内 FTS 驱动（`perseus_fts.c`，`fts=1`），它只在调试芯片本身时单独使用。

仓库补丁 `0004-touch-reader-init-hook.patch` 就是为此加的：把 `perseus_touch_init()` 挂进
`redwood_input_init()`，并把这个文件放进 `xnu/files/bsd/dev/perseus_touch.c` 以便构建时安装。

验证：上述改动 + 去掉 `fts=1` 后，触摸恢复（点按、拖动、滑动、返回手势都正常）。

### 2. 内核树被反复实验污染后的复原方法

排查显示问题时在 `MiniIOMobileFramebuffer.cpp` 上叠了十几层实验补丁，导致后续日志互相矛盾。
复原的办法是回到两个真实来源，而不是在坏树上继续改：

```
hackios 原始文件        $HACKIOS/xnu/files/iokit/Kernel/MiniIOMobileFramebuffer.cpp
+ 设备补丁              设备仓库的 xnu/patches/*
= 干净的显示驱动
```

同类需要一起复原的还有 `bsd/dev/redwood_adreno.c`、`iokit/Kernel/RedwoodGPU.cpp`、
`iokit/Kernel/MiniIOSurface.{cpp,h}`、`bsd/sys/redwood_input.h`、`bsd/dev/redwood_input.c`。
复原后内核 15,179,488 字节，`mi8_gpu`/`scanout:`/`flip: latched` 等实验字符串应为 0。

### 3. GPU：A630 能跑，显示链路还没接对

已确认（都是日志/像素证据）：

| 项 | 证据 |
| --- | --- |
| A630 上电、ZAP 认证、非安全模式 | `PAS_AUTH_AND_RESET: rc 0 … ZAP AUTHENTICATED`、`SECVID_TRUST_CNTL after: 0 (NON-SECURE MODE)` |
| 加速器服务发布 | `RedwoodGPU: the service is published` |
| Mesa + freedreno 出图 | `gl_test: freedreno; FD630; OpenGL ES 3.2 Mesa 25.0.7`，1080×2400 三角形 26% 覆盖率与几何一致 |
| CoreAnimation 走 GPU | `redwood-gl: an OpenGL ES 3 context for CoreAnimation … FD630`、`RedwoodGPU: submission … (24 buffers)` |

没有解决的：GPU 画出的帧没有正确显示到面板（花屏 / 黑屏），以及 CA 只提交两三帧就停。

对照三个同路线项目后的结论（这三份分析都只读源码）：

| 项目 | SoC / GPU | 关键事实 |
| --- | --- | --- |
| hackios-thyme（小米 10S） | SM8250 / A650 | **不写任何 DPU 寄存器**；显示控制器由引导器点亮后无人再动；`swap` 就是 CPU 把 IOSurface 缩放着拷进面板内存；呈现由常驻内核线程做，队列深度 2 |
| hackios-mi10ultra（小米 10 Ultra） | SM8250 / A650 | 同上，并明确 `MiniIOMobileFramebuffer.cpp` 头注释：*"There is no hardware behind it that we drive: a 'swap' copies the pixels … and 'vsync' is a timer."*；`fRowBytes` 取 GOP 的 `pixels_per_scanline*4`，**不是 width×4** |
| hackios-xnu-kernel-raphael（K20 Pro） | SM8150 / A640 | 同样的 CPU 拷贝模型，另加 TE（撕裂效应）行计数选窗口；文档承认"桌面卡顿"仍在 |
| UniXNU-polaris（MIX 2S） | SDM845 / **A630** | 同 SoC，但 **GPU 从未被驱动**：`No XNU GPU power, GMU/HFI, SMMU or rendering was ever performed`，锁屏是软件渲染 |

因此下一轮的方向是明确的：**不要动 DPU**，把 `present()` 做回"异步 + 有界队列 + CPU 缩放着拷进
`fBase`"，行宽用 `vinfo.v_rowbytes`，并核对 `fBase` 是否就是显示控制器正在扫描的那块内存。

### 4. 当前可用的启动参数

```
debug=0xc bootcpu=7 cpus=7 gic_timer_irq=19 rd=md0 ufs=2 root_apfs=ufs_userdata
ufs_shared_pa=0x00000000a1652000 touch_shared_pa=0x00000000a1655000
```

不要加 `fts=1`（见第 1 节）；GPU 相关参数（`gpu=1` 等）在显示链路修好之前不要与
`fb_flip`/`fb_native` 一起使用。
