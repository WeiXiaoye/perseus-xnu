# 开发记录

## 2026-11-06：第一次进到 iOS 16.5 桌面

**结果**：MIX 3 上 `launchd → backboardd → SpringBoard` 全部跑起来，桌面可见。

启动参数（当时的）：

```
debug=0xc bootcpu=7 cpus=7 gic_timer_irq=19 rd=md0 ufs=2 root_apfs=ufs_userdata
```

### 关键日志

```
second ramdisk at pa 188000000 size 400000 (md0); the payload ramdisk is md1
gic: v3, distributor …, virtual timer on PPI 19
ufs: 86 partitions of the phone's storage as /dev/ufs_NAME …
apfs: volume 0 "Boot" of container 0 (at 0 MB): 1 files, 7 directories
load_init_program: attempting to load /sbin/launchd
… launchd … SpringBoard … backboardd … powerd … wifid
```

### 这一路上修掉的东西

1. **虚拟定时器 PPI**：SDM845 是 `INTID 19`（PPI 3），基线写死 27 → 一个 tick 都没有，
   表现就是"卡在挂根、`loader_return_after` 也不响"。改成 `gic_timer_irq=19` 后内核一路走到 launchd。
2. **`boot_args.commandLine` 没有 NUL 结尾**：内核读到上一轮的 `fts_steps=6`，
   让"改成 3 还是卡"的几轮实验全部失效。补 NUL + 整个结构清零后参数才可信。
3. **payload 只有一张 ramdisk**：stage0（flashboot 的 `/sbin/launchd`）要挂 `md1` 才能 exec
   真正的 init；缺了就是 `stage0: cannot mount /dev/md1 on /redwood: No such file or directory` 然后 halt。
4. **日志**：loader 运行期只写自己的日志，内核环要等结束才写。改成周期写盘时
   `compose_live_log()`，正常重启也能拿到完整内核日志。
5. **root 卷格式**：sweet 线的 iOS 16.7 是 HFSX，hackios 要 APFS 的 16.5（20F66，iPhone X）；
   两者用户态与内核都不兼容，不能混用。

### 当前卡点：触摸

- 内核已有 ST FTS 驱动（`perseus_fts.c`，源自小米 8 的 `mi8_fts.c`，按 perseus 改了 GPIO79 / y-max 2339）；
- `fts_steps=2`（只读）拿到的现场：
  - `pin 31/32`（IRQ/reset）被固件配成**输出**、低电平；
  - `pin 33/34`（SDA/SCL）配置 `0x001`（输入、下拉），**电平 0**；
  - `pin 79`（`disp_vddio_vreg`）**完全没配置**（config `0x000`）；
  - `SE14` 时钟关着，但引擎可读、`protocol 3 (i2c)`；
  - `PM8998 L27` enable `0x80`（开），`L28(0x5b)`/`L29` enable `0`。
- 结论：**I/O 轨没上电**，上拉没电，总线一直是低电平 —— 不是驱动把总线写坏。
- `fts_steps=3`（上电）会让整机**立刻复位**，怀疑是直接写 RPMh RSC/TCS 请求 L28 导致；
  已加 `fts_noldo=1` 把这一步拆开，下一步先只验证 GPIO79 能否拉高。
